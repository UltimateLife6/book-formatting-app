# ADR-001: Monorepo beside the legacy app, with a structured manuscript model

- **Status:** Accepted for Phase 0 (foundation milestone)
- **Date:** 2026-10-14
- **Branch:** `rebuild/folio-loom-2-mobile`

## Context

Folio Loom 1.x is a Create React App web app. The audit (`docs/audits/legacy-audit.md`) found these problems:
- The manuscript is stored as overlapping plain strings in one localStorage key.
- EPUB output is invalid EPUB 2, and PDF output is rasterized.
- Authentication is fake.
- There is no native app.

2.0 requires native iOS and Android plus web, accounts, offline editing with cloud sync, and verifiable manuscript integrity. The legacy app is live (Vercel deploys from `main`), so it has to keep working while 2.0 is built.

## Decision

1. **Use npm workspaces in this repository, with the legacy app staying at the root.**
   - New code lives in `apps/`, `packages/`, `services/`, and `tooling/`.
   - The legacy `start`, `build`, `test`, and `lint` scripts and the Vercel config are unchanged. New scripts are prefixed `ws:`.
   - The legacy app moves to `legacy/` (or is deleted) only when 2.0 reaches parity.
2. **Use Expo (React Native) for mobile and Next.js for web.** Both consume the same TypeScript packages, and the packages ship their source.
3. **Adopt a canonical structured model** (`packages/book-model`): sections, then blocks, then marked runs. It has stable IDs and versioned zod schemas with strict validation and migrations. HTML is never the source of truth.
4. **Use Firebase** (Auth, Firestore, Storage) as the backend, with local SQLite (native) or IndexedDB (web) behind one `ManuscriptStore` interface. Sync is per section with revisions and conflict detection, and never overwrites silently.
5. **Do exports and export accounting server-side**, with an idempotent ledger keyed by `requestId`.
6. **Pin tooling per workspace.** The root keeps TypeScript 4.9.5 and ESLint 8 for CRA. The new workspaces use TypeScript ~6.0, Vitest 5, and Biome.

## Alternatives considered

- **Moving the legacy app into `legacy/` now.** Rejected for Phase 0 because it means changing Vercel's root directory and build settings for production.
- **pnpm or Turborepo.** pnpm isn't installed in this environment, and switching package managers would fight the existing npm `node_modules`. This can be revisited once the legacy app is gone.
- **A separate repository for 2.0.** Rejected because it would lose the shared history and fixtures, and the legacy chapter-detection tests port more easily in place.
- **Capacitor, wrapping the web app.** Rejected because the web app would need rewriting anyway, and a native editor experience matters for phone-first use.
- **Storing chapters as HTML or Markdown strings.** Rejected because it can't be validated, merges poorly, and is the source of the legacy escaping bugs.

## Consequences

- **Single React version.** Expo SDK 57 needs React 19.2.3 exactly, and npm hoists one React. The legacy app is pinned to 19.2.3 as well; its tests and build pass. Future Expo upgrades must move the legacy React in lockstep, or the legacy app must be retired first.
- **npm optional-dependency bug.** npm can drop native optional bindings (npm/cli#4828). Rolldown's platform bindings are listed explicitly in `tooling/package.json` and must be bumped together with Vitest.
- **Vercel preview builds** of this branch install every workspace, which is slower but harmless. Production still builds the legacy app from `main`.
- **DOCX parsing on device.** Mammoth is kept out of the mobile bundle. Native DOCX import goes through the server until an on-device path is proven.
